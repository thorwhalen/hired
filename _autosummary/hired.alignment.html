hired.alignment#

JD-vs-candidate alignment: classify each requirement honestly into four buckets.

Public surface:

  • schemas in hired.alignment.base (Requirement, RequirementRecord, AlignmentReport, and the enums),

  • the deterministic rubric in hired.alignment.rubric (classify(), assign_bucket(), apply_ai_leverage()),

  • the elicitation helpers in hired.alignment.elicitation (rank_clarifications(), is_decision_stable()),

  • calibrated confidence in hired.alignment.calibration (semantic_consistency(), calibrate_match() and its conformal MatchCalibrator ask/auto-decide rule),

  • deterministic report finalization in hired.alignment.assemble (finalize_report() — reclassify, recount, rebuild blockers/clarifications),

  • the injected-LLM analyzer in hired.alignment.analyzer (LLMAlignmentAnalyzer, analyze_jd() — decompose, retrieve, quote-then-answer, grounding gate, deterministic aggregate_verdict()),

  • rendering in hired.alignment.report (render_report() dispatching to render_report_markdown() / render_report_html()).

The intelligence (judging transfer distance, trainability, evidence) is supplied by the hired-align skill (Claude as brain) or an injected LLM; this package provides the schemas, deterministic scoring, and rendering. See misc/docs/DESIGN.md §6-8.

hired.alignment.apply_calibration(record, samples, *, calibrator=None, meaning=None, is_match=None)[source]#

Set record’s confidence from sampled judgments, and its decision if calibrated.

samples are several independent judgments of the same requirement (match states, by default). The record’s confidence becomes confidence_level() of their agreement and its match_score match_share(); with a calibrator, calibrated_decision is its decide(), which should_ask() honours (without one it is cleared: new samples supersede an old decision, so re-apply, or clear it, once an answer settles the requirement). The match state stays the analyst’s: an ask questions a claim, it does not overturn it. Returns the record, changed in place.

>>> from hired.alignment.base import Requirement
>>> rec = RequirementRecord(requirement=Requirement(text="Kafka"), match_state="confirmed")
>>> rec = apply_calibration(rec, ["confirmed", "confirmed", "unknown"])
>>> rec.confidence.value, round(rec.match_score, 2), rec.calibrated_decision
('medium', 0.67, None)
Return type:

RequirementRecord

hired.alignment.calibrate_match(scores, labels, *, false_accept_rate=0.05, miss_rate=0.1)[source]#

Fit the ask/auto-decide rule on held-out judgments with known truth.

scores are match scores in [0, 1] (say match_share() of sampled judgments), labels whether each was truly a match. Each class gets its own threshold (Mondrian split conformal): false_accept_rate bounds how often a true non-match is auto-accepted, miss_rate how often a true match is auto-rejected. Keep the held-out set apart from anything used to tune the scoring, or the bound does not hold.

Return type:

MatchCalibrator

hired.alignment.make_embedding_retriever(embed=None, *, min_similarity=0.0)[source]#

A semantic retrieve for LLMAlignmentAnalyzer: the k facts most cosine-similar to the requirement, so adjacent skills (RabbitMQ for a Kafka requirement) reach the judge.

embed maps texts to vectors (default openai_embed(), the ai extra). Fact vectors are cached by text, so each fact is embedded once per retriever.

>>> vocab = ('kafka', 'rabbitmq', 'queue', 'french')
>>> def embed(texts):  # a fake: 'kafka' and 'rabbitmq' are both message queues
...     return [[t.lower().count(w) + ('queue' == w) * ('kafka' in t.lower() or
...              'rabbitmq' in t.lower()) for w in vocab] for t in texts]
>>> fs = [Fact(statement='Ran RabbitMQ in prod'), Fact(statement='Speaks French')]
>>> retrieve = make_embedding_retriever(embed)
>>> [f.statement for f in retrieve(Requirement(text='Kafka'), fs, k=1)]
['Ran RabbitMQ in prod']

The k facts sharing the most words with the requirement.

Lexical, so it misses an adjacent skill named in different words (RabbitMQ for Kafka). When the whole knowledge base fits in k (and small_kb_passes_all), every fact is passed, best overlap first, so the judge sees the adjacent skill anyway; a negation fact sharing no word is still dropped, so an unrelated “does not …” cannot back a contradiction. Otherwise facts sharing no word are dropped (none if none do). For large KBs, inject make_embedding_retriever().

>>> from hired.candidate.base import Fact
>>> fs = [Fact(statement='Ran Kafka clusters'), Fact(statement='Speaks French')]
>>> [f.statement for f in retrieve_facts(Requirement(text='Kafka streaming'), fs)]
['Ran Kafka clusters', 'Speaks French']
>>> [f.statement for f in retrieve_facts(Requirement(text='Kafka streaming'), fs, k=1)]
['Ran Kafka clusters']
Return type:

list[Fact]

hired.alignment.semantic_consistency(samples, *, meaning=None)[source]#

The agreement of sampled answers, clustered by meaning (default: equality).

meaning maps an answer to its meaning: a normalised label, an entailment cluster id. Answers that mean the same count as agreeing however worded.

>>> c = semantic_consistency(["Yes", "yes", "no", "YES "], meaning=lambda s: s.strip().lower())
>>> c.majority, c.agreement, round(c.entropy, 3)
('yes', 0.75, 0.811)
>>> semantic_consistency([]).agreement
0.0

hired.alignment.should_ask(record)[source]#

Whether to route this record to a clarifying question.

Ask only when it’s UNKNOWN on an OPEN field and decision-relevant — the “don’t assume absence from silence” rule. CONTRADICTED facts and closed-field unknowns are real gaps, not questions. A decision-relevant CONFIRMED or CONTRADICTED record whose calibrated decision is ask (sampled judgments too inconsistent for the conformal rule, see hired.alignment.calibration) is asked about too: “never exaggerate” means a shaky match is confirmed first, and a shaky absence is not assumed. An UNKNOWN follows the rule above.

bool
