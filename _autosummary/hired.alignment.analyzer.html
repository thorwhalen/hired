hired.alignment.analyzer#

Library-mode autonomous alignment analysis, driven by an injected LLM.

The non-interactive counterpart of the hired-align skill: given a job description’s text and a candidate’s facts, produce a draft AlignmentReport that save_alignment() finalizes and persists. The pipeline is a grounded per-requirement judge:

  1. decompose — the LLM splits the JD into atomic Requirement records;

  2. retrieve — the most relevant facts are pulled from the knowledge base (lexical overlap by default, every fact when the KB fits in k; inject retrieve=make_embedding_retriever() for semantic retrieval);

  3. quote-then-answer — the LLM must quote a verbatim span of a cited fact before it states a match;

  4. gate — a quote that is not verbatim in the cited fact, a CONTRADICTED judgment not backed by a negation fact, or (with nli) a quote that does not entail the requirement, drops the judgment to UNKNOWN: it becomes a question for the candidate, never an invented match or gap;

  5. aggregate — the verdict and fit band are computed deterministically from the records (aggregate_verdict()). The LLM explains; it never sets the score.

Like LLMResumeAgent, the analyzer is lazy and injectable: openai (the ai extra) is imported only when no client is given, and no key is read at construction. client is anything exposing the OpenAI-style chat.completions.create.

The verdict and fit band, computed from classified records alone.

A blocking gap (a gate-keeper that is a hard gap or contradicted) means do not apply; otherwise the weighted coverage picks the recommendation. Confidence comes from how much of the JD is resolved, not from the LLM.

>>> from hired.alignment.base import MatchType
>>> rec = classify(RequirementRecord(requirement=Requirement(text='Python'),
...     match_state='confirmed', match_type=MatchType.DIRECT, candidate_level=4))
>>> verdict, band = aggregate_verdict([rec])
>>> verdict.recommendation.value, band.value, verdict.confidence.value
('apply', 'great', 'high')

hired.alignment.analyzer.make_embedding_retriever(embed=None, *, min_similarity=0.0)[source]#

A semantic retrieve for LLMAlignmentAnalyzer: the k facts most cosine-similar to the requirement, so adjacent skills (RabbitMQ for a Kafka requirement) reach the judge.

embed maps texts to vectors (default openai_embed(), the ai extra). Fact vectors are cached by text, so each fact is embedded once per retriever.

>>> vocab = ('kafka', 'rabbitmq', 'queue', 'french')
>>> def embed(texts):  # a fake: 'kafka' and 'rabbitmq' are both message queues
...     return [[t.lower().count(w) + ('queue' == w) * ('kafka' in t.lower() or
...              'rabbitmq' in t.lower()) for w in vocab] for t in texts]
>>> fs = [Fact(statement='Ran RabbitMQ in prod'), Fact(statement='Speaks French')]
>>> retrieve = make_embedding_retriever(embed)
>>> [f.statement for f in retrieve(Requirement(text='Kafka'), fs, k=1)]
['Ran RabbitMQ in prod']

hired.alignment.analyzer.retrieve_facts(requirement, facts, *, k=5, small_kb_passes_all=True)[source]#

The k facts sharing the most words with the requirement.

Lexical, so it misses an adjacent skill named in different words (RabbitMQ for Kafka). When the whole knowledge base fits in k (and small_kb_passes_all), every fact is passed, best overlap first, so the judge sees the adjacent skill anyway; a negation fact sharing no word is still dropped, so an unrelated “does not …” cannot back a contradiction. Otherwise facts sharing no word are dropped (none if none do). For large KBs, inject make_embedding_retriever().

>>> from hired.candidate.base import Fact
>>> fs = [Fact(statement='Ran Kafka clusters'), Fact(statement='Speaks French')]
>>> [f.statement for f in retrieve_facts(Requirement(text='Kafka streaming'), fs)]
['Ran Kafka clusters', 'Speaks French']
>>> [f.statement for f in retrieve_facts(Requirement(text='Kafka streaming'), fs, k=1)]
['Ran Kafka clusters']
Return type:

list[Fact]
